# MiniGRAMS LArTPC Analysis Pipeline

**Author:** Jonathan LeyVa
**Version:** 2.0 (Jan 26, 2026)

This repository contains the full signal processing pipeline for the MiniGRAMS Liquid Argon TPC (LArTPC). It handles data conversion, baseline correction (using the `grams_tools` library), and the generation of compiled analysis plots.

## Prerequisites

1.  **Clone the repository:**
    ```bash
    git clone [https://github.com/Oppenheimer1904/MiniGRAMS_Analysis.git](https://github.com/Oppenheimer1904/MiniGRAMS_Analysis.git)
    cd MiniGRAMS_Analysis
    ```

2.  **Install dependencies:**
    ```bash
    pip install -r requirements.txt
    ```

## Libraries
**`grams_tools.py`**

This library contains the baseline correction algorithms used for both SiPM and CSP channels.
* **SiPM Channels:** Utilizes **iterative asymmetric clipping** to robustly handle high Dark Count Rates (DCR) typical in room-temperature GAr data.
* **CSP Channels:** Applies a **median filter** followed by clipping to reject EMI glitches and switching power supply noise.

* **Spectral Analysis:** Contains the math to perform FFT analysis on waveform segments provided and convert to power spectral density arrays (PSDs) to express the frequency domain power content of a trace.

**`detector_config.py`**

This library contains a mixture of hard-mappings and algorithms to generate channel maps for specific run configurations. 
The run configurations are extracted from binary filenames and the mapping info is embeded into the converted HDF5 files.

e.g., a binary file might have a tag in it's filename called '_light-only_'. In this case the mapping structure will be generated
to reflect a setup where a CAEN V2730 is fully populated with light channels and the even CAEN channels are VUV while the odd 
channels are VIS

As we put together more run configurations (e.g., syncing multiple V2740B's with our V2730), we can update this script to generate the 
appropriate channel mapping before that info is embeded in a converted HDF5.

### Workflow

## Step 1: Data Conversion
Converts raw binaries generated by CAEN's WaveDump2 firmware (in 'file-per-board' configuration) into structured HDF5 files. The data is converted with 1:1 compression and automatically sorted into directories based on the run confgiuration.

**Usage:**
*Note: 8 CPU cores have been found to be optimal for the Aramaki lab server with this script.*
```bash
python 01_Bin2HDF5_FPB.py /path/to/raw_data/ --output /path/to/destination --workers 8
```
## Step 2: Embed Baseline Correction
Calculates a baseline correction value for every channel across all events using grams_tools.py. It injects a dataset of 32-bit float correction values directly into the HDF5 files.

Uses the embeded channel mapping information from the previous step to know which baseline correction algorithm to use for a given
channel that it is working on. 

* Subsequent studies can apply baseline correction with near-zero computational expense by reading this embedded table.
* This script only targets .h5 files and modifies them in place.

**Usage:**
* User must define the pre-trigger window in microseconds by passing, e.g. '--pre_trigger 16.0' in the command. 

*Note: 8 CPU cores have been found to be optimal for the Aramaki lab server with this script.*
* Typical example for combo data:
```bash
python 02_calc_baselines.py /path/to/hdf5_data/ --pre_trigger 16.0 --workers 8
```

* Although chunking was implemented, be ready to kill the script with the following terminal command if RAM runaway is dangerously fast:
```bash
sudo pkill -f 02_calc_baselines.py 
```

## Step 3: Generate Plots
Generates a PDF containing a compilation of plots for all events in an HDF5 file. 

**Output:** 
* User can pass an integer or 'all' argument to select number of events to stich together in a PDF. If the number of requested events is 
greater than 3000, the user will be warned and might need to use the --force argument if they are sure that there is enough RAM headroom to proceed with plot generation. 
* Typical data saving with WV2 limits each file to 500 events. If the requested number of events is greater than the number of events in the HDF5 file, the script will continue collecting events from subsequent files until the desired number of events is reached. It will stitch all of these events into a single PDF file that can be viewed through VSCode or downloaded locally

* User must not omit the '--threshold' argument, if you know you are converting pedestal data, use '-t 0.0' (although it will technically ignore anything you pass if it also detects the data to be pedestal data)
* If the script detects any kind of pedestal tag in the HDF5 filename, it will not use the threshold provided by the user since our pedestal data is typically triggered externally with a function generator
* Plots will be dumped in a 'Plots' sub-directory that lives on the same level as the HDF5 files passed to the script

**Plot layout:** 
* Combo style: Top rows show X & Y charge channels. Bottom rows show VUV & VIS SiPM channels. 
* Light focused style: Shows VUV & VIS side by side
**WARNING: HIGH RAM USAGE** This is a memory intensive script. Please consider the following:
* Use htop to monitor the server when this script is running
* Ensure the server has 12-16GB of headroom to run this script with 4 cores activated 
* Coordinate with other server users to avoid more than one person running RAM intense scripts at the same time
* Although chunking was implemented, be ready to kill the script with the following terminal command if RAM runaway is dangerously fast:
```bash
sudo pkill -f 03_mass_plotter.py 
```
**Usage:**
*Note: 4 CPU cores have been found to be optimal for the Aramaki lab server with this script. Expect up to 12GB RAM consumption while script runs*

* Typical example for combo data:
```bash
python 03_mass_plotter.py /path/to/hdf5_data/ --events all --threshold -60 --workers 4
```
* Typical example for pedestal data:
```bash
python 03_mass_plotter.py /path/to/hdf5_data/ --events 100 --threshold 0 --workers 4
```

## Step 4: Spectral Analysis
Generates a PNG for each acquistion showing an event averaged PSD plot. 

**Output:** 
* User can specify the number events to contribute to the averaged PSD data by using '--events'. Deafults to 100 events
* Plots will be dumped in a 'Plots' sub-directory that lives on the same level as the HDF5 files passed to the script

**Plot layout:** 
* Script will identify the run configuration based on the HDF5 file it is given. The plot formats are very similar arrangment to those yielded by the 03_mass_plotter.py script
* Combo style: Bottom rows show X & Y charge channels. Top rows show VUV & VIS SiPM channels. 
* Light focused style: Shows VUV & VIS side by side

*Note: 8 CPU cores have been found to be optimal for the Aramaki lab server with this script.*
* Typical example:
```bash
python 04_calc_baselines.py /path/to/hdf5_data/ --events 250 --workers 8
```
